# ProjectHub V1.5：AI 智能周报生成器实施计划

> **实施者要求：** 使用 `executing-plans` 技能在当前会话按任务顺序执行；如用户另行选择代理分工，再使用 `subagent-driven-development`。步骤以复选框跟踪。本文件不自动授权并行代理或 Git 提交。

**目标：** 在 ProjectHub 中完成多项目本人 Git／日志汇总、人工补充要点、候选成果选择、周报版本历史及固定 Excel／Markdown 导出。

**架构：** 独立周报模块复用系统 Git runner、AI 配置和发送确认模式；SQLite v3 存储偏好、周报组、版本及来源快照。React 使用准备／编辑两个视图与历史列表，导出只消费已保存版本。

**技术栈：** 现有 React 19、TypeScript、Tauri 2、Rust、rusqlite、chrono、serde、reqwest；固定 XLSX 模板通过 ZIP 容器读写，具体依赖须先通过任务 1 的工具链兼容检查。开发期独立校验可用已加载的工作区 Python／电子表格工具，生产不依赖它们。

## 全局约束

- 验收依据：`docs/superpowers/specs/2026-10-16-v1.5-weekly-report-design.md`，已获用户确认设计基线。
- 本周为周一至周五，包含周五全天；自定义日期结束日采用次日 00:00 排他边界，保存本地时区及 UTC 边界。
- 当前 HEAD 可达提交，作者身份为已确认姓名／邮箱的任一精确匹配，提交者时间归属周次；日志按自身业务日期筛选。
- 默认提交说明＋文件名＋日志，Diff 逐文件勾选并预览；工作区未提交内容不纳入。
- 工作成果 4 条、困难 3 条、计划 4 条、感悟一段；人工要点为空时对应 AI 内容为空。
- 每次最多 20 项目，每仓库扫描 20,000 提交、纳入 500 条匹配提交；一轮最多 200 日志、100 个 Diff 文件；Git 并发 2，完整请求 64 KiB。
- 单条正文 4,000 字符、感悟 8,000 字符、候选 100 条；超限显式失败或重新选范围，不静默截断。
- 预览单次令牌 10 分钟，绑定输入／仓库／日志／模型／导入代次，取消后忽略晚到结果。
- 新生成保存为新版本，不覆盖旧稿；Excel＋Markdown 读取同一保存版本，不再次生成。
- 保留原项目、标签、发现、AI 配置和开发进度功能；浏览器预览不伪造本地 Git、模型或周报历史。

```tsx
  return <OutcomeEditor outcomes={fiveOutcomes} selectedIds={ids} onChange={setIds} />;
}

it('最多选择四条，取消后可以选择另一条', async () => {
  const user = userEvent.setup();
  render(<ControlledEditor />);
  const items = screen.getAllByRole('checkbox');
  for (const item of items.slice(0, 4)) await user.click(item);
  await user.click(items[4]);
  expect(screen.getByRole('alert').textContent).toContain('最多选择 4 条');
  expect((items[4] as HTMLInputElement).checked).toBe(false);
  await user.click(items[0]);
  await user.click(items[4]);
  expect((items[4] as HTMLInputElement).checked).toBe(true);
  expect(items.filter(item => (item as HTMLInputElement).checked)).toHaveLength(4);
});
```

上述合同中的 `OutcomeEditor` 自行显示超限提示，仅把合法选择交给 `onChange`；父组件以真实 React state 驱动 `selectedIds`。沿用现有断言库，不为单个示例引入额外依赖。
