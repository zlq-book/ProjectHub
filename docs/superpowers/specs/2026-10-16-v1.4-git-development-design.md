# ProjectHub V1.4：Git 与开发进度管理设计

日期：2026-10-16。状态：已获用户确认，源码实现、自动化验证与 Windows 打包完成；原生 GUI、真实供应商和安装执行未实测。

## 1. 已确认目标与口径

在 ProjectHub 内查看各项目的工作区变化、提交历史、代码差异与开发活跃情况，并管理开发日志和任务、关联真实 Git 提交。

用户已明确选择：**开发活跃度默认统计当前分支、全部作者**。具体解释为当前分支 HEAD 可达的本地提交历史，每个提交 ID 只计一次，默认包含合并提交。分离 HEAD 则统计当前检出的提交及其可达历史，并明确显示该状态。首版不增加“仅本人”或“全部本地分支”的切换，避免混淆已确认口径。

| 模块 | 首版闭环 | 顺序 |
| --- | --- | --- |
| Git 分支与文件提醒 | 列表看到分支与未提交数，进入工作区查看文件及暂存状态 | 第一阶段 |
| 提交历史与差异 | 分页历史 → 提交详情 → 文件列表 → 逐文件 Diff | 第一阶段 |
| 活跃度与 AI 摘要 | 日／周／月趋势，明确最近提交时间；主动选择变更生成 AI 总结 | 第二阶段 |
| 日志与任务 | 新建／编辑日志、待办／进行中／已完成任务，手动关联提交 | 第三阶段 |

三个阶段属于同一 V1.4 交付范围。Git 查询与本地工作记录分别建模，前两阶段独立可用，第三阶段复用真实提交选择器。

## 2. 当前代码依据

- `src-tauri/src/services/git.rs` 目前只返回是否仓库、当前分支、origin 远程；没有文件状态、历史、Diff 或活跃度。
- 当前 Git 子进程帮助函数先等待退出，再读 stdout，且只取 64 KiB。历史与 Diff 不能直接沿用该方式，需要改为并发排空输出、限制容量和超时终止。
- `src/components/ProjectDetail.tsx` 在右侧详情读取 Git 信息；`ProjectTable.tsx` 当前为名称、简介、技术栈、路径、最近更新五列。
- `Project.updatedAt` 是项目资料更新时间，`lastOpenedAt` 是 ProjectHub 打开记录；二者不能作为 Git 开发活跃时间。
- `src-tauri/src/db/mod.rs` 当前数据库版本为 1，只有项目和设置；导入会按自己的 schema 重建已校验的数据。新增日志／任务必须同步改造迁移、备份和导入。
- 现有 AI 助手已有配置、严格意图、读取范围及取消机制，但对“最近开发／代码更新”有能力不足提示。V1.4 接入真实 Git 来源后，需要一并更新该能力判断。
- 本机 Git 为 `2.39.1.windows.1`；ProjectHub 源码目录本身没有 `.git`。设计不以此推断用户已登记项目是否为 Git 仓库，也不初始化或提交任何仓库。

## 3. 方案比较

| 方案 | 优点 | 代价 |
| --- | --- | --- |
| 沿用系统 Git，增加开发进度工作区，推荐 | 与用户本地仓库结果一致，复用现有依赖，复杂 Diff 有足够空间 | 需要可靠的进程协议、缓存和状态解析 |
| 全部放入右侧详情 | 入口集中，主页面改动少 | 窄栏难以阅读代码差异和任务列表 |
| 引入独立 Git 库和完整项目管理系统 | 可提供更多仓库操作和团队流程 | 新依赖及语义适配成本高，超出本地只读 Git 与轻量任务范围 |

采用推荐方案。V1.4 产品里程碑与现有 `0.3.0` 包版本不同；正式发布时统一更新前端、Cargo、Tauri 配置及界面版本显示至 `1.4.0`，不只改其中一处。

## 4. 页面与操作

### 4.1 主项目库

保留现有布局与五列结构。在名称单元格下增加一行紧凑 Git 信息，例如“main · 未提交 3”；异常状态用文字和标识共同表达。原时间列明确标为“资料更新”，保留其原数据与排序含义。

详情增加 Git 概览：分支、工作区状态、未提交数量、当前 HEAD 提交时间，以及“查看开发进度”入口。用户无需打开 IDE 即可查看真实代码状态。

### 4.2 开发进度工作区

左侧导航增加“开发进度”。中间区域先展示跨项目概览：项目、分支、工作区状态、未提交数、最近提交、待办／进行中／已完成数量；支持名称搜索和异常状态筛选，未读取和读取失败独立展示。

点击项目进入该项目开发工作区，顶部显示项目名称、仓库范围、分支、刷新时间和返回概览；内部为“工作区／提交历史／活跃度／开发日志／任务”五个页签。提交 Diff 在中间区域按文件阅读，不挤进右侧 350px 详情。

右侧仍只在项目详情与 AI 助手间切换，不增加第四个主栏。进入代码差异页时默认暂时收起右栏，返回后恢复原状态。窄屏沿用现有单工作区切换与返回行为。

### 4.3 刷新与反馈

- 首先查询可见项目和当前选中项目；后台最多并发 2 个 Git 进程，避免对所有项目高频扫描。
- 页面处于前台时，可见工作区状态每 15 秒刷新；手动刷新即时触发。窗口隐藏后停止定时查询，恢复时检查过期数据。
- 每份结果包含读取时间、HEAD 和完整性状态；旧缓存标注“数据待刷新”。超时、目录不可用或 Git 缺失不能展示为“工作区干净”。
- 历史和活跃度绑定读取时的 HEAD；分支或 HEAD 变化后清空旧分页、使相关缓存失效。切换项目和取消后的晚到结果不得覆盖当前界面。
- 非 Git 项目仍可以使用日志和任务；Git 部分显示未初始化，不生成示例提交或趋势。

## 5. Git 工作区状态

使用稳定的机器可读状态协议，区分已暂存、未暂存、未跟踪和冲突，支持修改、新增、删除、重命名、类型变化及子模块摘要。重命名保留新旧路径。

未提交总数按逻辑文件条目去重：同一文件同时暂存和再次修改，总数只算 1；已暂存和未暂存分组可以同时包含该文件，分组数不要求相加等于总数。重命名按一项变化计数。未跟踪目录展开到文件，忽略文件不计入。

工作区展示文件状态、所属分组和路径。查看已有文件的 Diff 时分开选择“暂存区”或“工作区”；未跟踪文件只展示路径、状态及普通文本预览入口，用户明确选择后才按大小限制读取，不能伪装成已提交的代码差异。冲突和二进制文件明确提示，V1.4 不处理冲突解决。

状态解析使用 NUL 分隔，不能按换行拆文件名；XY 同时表达暂存区与工作区状态。官方依据：[Git status](https://git-scm.com/docs/git-status#_porcelain_format_version_2)。

## 6. 提交历史与 Diff

- 每页 30 条，显示短提交 ID、作者姓名、提交时间和说明；展开时可查看完整说明、完整 ID、作者时间与提交时间。
- 查询固定到本次 HEAD，游标不可用于另一项目或另一 HEAD。提交、文件和 Diff 使用后端返回的标识，路径与提交表达式不作为任意命令透传。
- 选中提交后加载变更文件，再按需加载单文件 Diff。二进制仅显示变化摘要；删除、重命名、根提交、空提交都必须有明确结果。
- 普通提交对父提交比较；根提交对空树比较；合并提交默认对第一父提交比较，明确标注该口径。文件列表、增删行与 Diff 必须采用相同的比较基准。
- 展示新增／删除行和变更文件数。二进制的行数为“不适用”，不能填 0 伪装成无变化。
- 同时支持查看当前未提交变化，但不在 V1.4 提供提交、暂存、还原、切分支、合并、推送等写仓库操作。

文件路径按字面值处理，Diff 禁用外部差异驱动和 textconv，避免读取差异时执行仓库配置的外部转换器。官方依据：[Git diff](https://git-scm.com/docs/git-diff)。

## 7. 开发活跃度

### 7.1 统一范围与时间

- 当前分支 HEAD 可达历史、全部作者，每个完整提交 ID 只计算一次，包含合并提交。子模块和其他独立项目不混入同一项目统计。
- 提交统计采用提交者时间；作者时间仍可在详情查看。UTC 用于传输和保存，图表按应用本地时区的自然日期归桶；周一为每周起点，历史跨时区／夏令时遵循同一时区规则。
- “最近开发（当前分支最新提交）”使用 HEAD 提交的提交者时间，界面同时说明来源。它代表已提交的开发活动，不包含尚未提交的编辑；日志记录时间和资料更新时间独立展示。
- Git 没有提交时显示“暂无提交”；Git 无法读取时显示未知。不能把未打开、无 Git、无已提交记录都称作“长期未开发”。

### 7.2 指标与趋势

日视图默认最近 30 天，周视图最近 12 个自然周，月视图最近 12 个自然月，均包含当前未结束周期。显示所选周期提交总数、活跃日期数量、每个时间桶的提交数及最近提交时间。支持选择时间范围，最多回看 2 年。

完整统计后，无提交日期补 0；若达到读取上限或发生错误，标注统计未完成，不能把未读取日期补为确定的 0。图表提供可读表格和明确图例，不依靠颜色单独表达状态。

提交时间异常、历史重写、浅克隆的历史边界均可影响统计，结果展示当前 HEAD、范围和完整性。使用日期过滤时须遍历可达历史后过滤，避免遇到一个较早时间的提交就漏掉其他符合条件的记录。官方依据：[Git log 的日期过滤](https://git-scm.com/docs/git-log#Documentation/git-log.txt---since-as-filterltdategt)、[提交时间格式](https://git-scm.com/docs/git-log#_pretty_formats)。

提交频次仅展示活动，不换算成开发效率、代码质量或项目完成百分比。

## 8. AI 变更摘要与助手接入

### 8.1 主动生成摘要

用户在提交详情或指定的未提交变化上点击“AI 总结”，先展示提交／暂存范围、选中文件、模型服务和拟发送的文本。默认包含提交说明、文件变化和必要的有限文本 Diff；不附加绝对路径、作者邮箱、API Key 或个人备注。

文件由用户明确选择；独立环境文件、私钥／证书、凭据文件及二进制默认排除，用户可以预览其余待发送文本。Diff 本身仍可能含业务代码与敏感文本，不能因做了字段排除就宣称完全脱敏。

确认发送后生成：主要改动、涉及模块、兼容性或潜在风险、值得人工检查的事项。每条结论引用提交或文件；未执行测试时不能写“测试已通过”。内容不完整时明确说明。结果仅展示，可编辑后点击“保存为开发日志”，不会自动修改任务状态或写入仓库。

沿用现有 API 配置与密钥保存；新摘要功能采用独立 Git 资料发送确认，不把之前的 README／元数据同意当作发送源码 Diff 的授权。

### 8.2 现有助手能力更新

新增固定的 Git 状态、提交历史、活跃度只读工具和变更摘要建议工具，UI 与助手共享同一 Git 服务及统计口径，不复制一套指标算法。可回答“哪些项目超过一个月没有提交”“这个项目还有哪些未提交文件”，结果链接到真实项目和提交。

移除“完全没有 Git 开发时间数据”的一概拒绝；新逻辑按真实仓库读取结果区分有提交、无提交、非 Git 和读取失败。`Project.updatedAt` 仍只代表资料时间。

每轮助手 Git 查询最多 20 个项目，超过时先提示缩小范围或分批；现有普通元数据检索的每轮 100 个项目限制继续有效。模型不获得任意 Git 命令、Shell 或仓库写入工具。

## 9. 开发日志与任务

### 9.1 日志

支持新建、编辑、查看和确认删除。字段：标题、日志日期、正文、创建／修改时间、可选关联提交；标题 1–200 字，正文最多 16000 字。日志日期默认今天，允许补记历史日期。以纯文本／受限展示处理正文，不执行其中的 HTML 或脚本。

可从提交详情创建一条草稿，或把 AI 摘要转为可编辑日志草稿；只有用户保存后落库。

### 9.2 任务

字段：标题、描述、状态、创建／修改时间、完成时间、可选关联提交。标题 1–200 字，描述最多 8000 字。状态固定为“待办／进行中／已完成”，支持列表分组、创建、编辑、切换状态和确认删除。

完成时间只在进入已完成状态时记录，重新打开任务则清空；修改内容不自动切换状态。关联提交不会自动把任务标记完成，提交数量也不推导任务进度。

展示真实的各状态任务数，不增加团队权限、复杂工作流、迭代管理、工时或自动提醒。

### 9.3 提交关联

日志和任务均可手动选择多条提交，一条提交可被多个记录关联。同一记录对同一仓库的同一完整提交 ID 只关联一次。后端验证项目范围与提交对象类型后保存，不能仅凭用户输入的任意字符串建立 Git 操作目标。

保存完整提交 ID、仓库来源与提交标题／姓名／时间快照。分支移动后，能定位到对象则仍可查看；历史重写或对象被回收时保留关联快照并显示提交当前不可读取，不删除日志或任务。

项目重新定位到不同仓库时，旧关联保留原仓库来源，不自动指向新仓库的同名分支。

## 10. 数据与备份

新增独立开发空间、日志、任务、提交关联四类数据：

| 数据 | 主要职责 |
| --- | --- |
| `development_spaces` | 关联项目 ID，保留项目名称／路径和仓库来源快照 |
| `development_logs` | 日志内容、日期与版本 |
| `development_tasks` | 任务内容、状态、完成时间与版本 |
| `development_commit_links` | 关联日志或任务（二者恰有一个），保存完整提交 ID 与来源快照 |

主键使用本地 UUID；写入时校验空间与目标记录一致，防止跨项目关联。日志／任务采用递增版本进行更新冲突检测，状态变更及关联保存同一事务提交。开发数据的更新时间不写回 `Project.updatedAt`。

移除项目索引时保留开发空间及记录快照，空间解除当前项目绑定，可在开发进度页“已移除项目”中查看；重新关联必须用户手动选择，不按同名项目自动合并。删除日志或任务前提示关联数量，只删除其关联记录，Git 提交对象不受影响。

数据库迁移到版本 2，迁移与校验在事务内执行；原项目／设置保留。备份同时包含四类开发数据；导入只读取经过校验的字段，按应用自己的 schema 重建关系和约束，不复制外来触发器或未经验证的结构。

接受版本 1 的旧备份；导入提示明确说明旧备份没有日志和任务，恢复后这些记录为空。替换前自动备份当前完整数据库，不能让旧的开发记录串到恢复后的项目上。版本 2 的备份恢复日志、任务及关联；旧软件拒绝新版备份。

导入成功后，使助手建议、Git 分页、统计缓存、任务／日志编辑快照一并失效，重新载入项目库。Git 缓存为内存派生数据，不进入备份。

## 11. 查询协议与性能边界

- 命令由 Rust 白名单构造，不调用 Shell。提交 ID、文件标识、项目 ID 均校验；文件参数按字面值传递，禁止透传任意参数或引用表达式。
- 读取进程同步排空 stdout/stderr；达到字节上限或超时终止进程并回收。状态最多 5 秒，历史／Diff 最多 10 秒，单项目统计最多 15 秒；取消后不再显示晚到结果。
- 状态最多 5000 个文件、输出最多 4 MiB；达到上限时数量标为“至少 N 个”，不能声称完整。
- 提交文件列表最多 2000 项；单文件文本 Diff 最多 256 KiB 或 5000 行，明确显示截断。AI 完整序列化请求（含系统提示与包装）最多 64 KiB，超限让用户减少文件或确认有标记的节选，不静默删减关键内容。
- 活跃度最多检查 20000 个可达提交或 15 秒，以先到为准，未完成的统计返回部分状态。超大仓库可缩短范围，不能把限制包装成完整历史。
- 只读设置包括禁用可选索引锁、分页器、外部 Diff／textconv、fsmonitor 外部调用及签名验证进程；继续清除外部仓库定位环境变量，不长期占用数据库写锁。
- 不自动 fetch。浅克隆标注可见历史范围；部分克隆先检查禁用懒获取的能力，不能可靠保证离线时停止该项读取并给出说明，不借用户浏览历史的操作隐式补齐远程对象。相关官方说明：[禁用懒获取](https://git-scm.com/docs/git#Documentation/git.txt---no-lazy-fetch)。不假定本机 Git 2.39 已支持新版选项。
- 状态缓存 15 秒；历史和统计缓存最多 5 分钟，HEAD、仓库来源或范围改变立即失效。统计结果保留实际读取时间，所有全库概览明确已读取／未读取项目数。

## 12. 代码职责与分阶段交付

第一阶段：将 Git 进程、状态解析、历史与 Diff 分为独立模块，扩展 `GitInfo` 为明确的仓库快照类型；增加服务适配、开发进度概览及项目工作区。原有详情分支／远程显示复用该来源，避免重复事实来源。

第二阶段：加入活跃度原始提交时间查询与本地时区归桶、趋势图和可读表格；接入受限的 AI 摘要、真实 Git 助手工具与发送预览。Git 查询共享同一来源与缓存，AI 不自行推算统计。

第三阶段：实现数据库版本 2 迁移、日志、任务、提交关联及项目移除归档；同步升级备份／导入、编辑冲突及页面状态失效处理。最后统一版本、完整回归与 Windows 打包记录。

主要新增目录为 `src/components/development/`、对应服务／类型／样式，和 `src-tauri/src/services/git/`、`src-tauri/src/db/development.rs`。`App.tsx` 只负责导航和工作区协调，不继续堆入 Git 协议及任务业务。

## 13. 验收标准

1. 干净、暂存、未暂存、同时暂存又修改、未跟踪、删除、重命名、冲突、子模块均有真实临时仓库用例；中文、空格、换行、特殊字符文件名不破坏解析。未提交总数不会重复计算同一逻辑文件。
2. 非仓库、Git 缺失、空仓库、分离 HEAD、worktree、仓库损坏／权限异常独立显示。项目目录不可用时仍保留工作记录。
3. 历史分页绑定同一 HEAD；切分支、外部新提交和历史重写后旧请求／旧游标失效。根提交和合并提交的文件数、行数、Diff 比较基准一致。
4. 大输出不因管道缓冲区阻塞而挂起；超限、超时、取消、非 UTF-8 输出、二进制和缺失对象都有可检查结果，读取流程不执行外部 Diff 或转换程序。
5. 活跃度在固定参考时间、UTC／本地时区、跨日／周／月、无提交日期、重复可达历史和时间不单调的提交下得到正确结果；指标对应当前分支全部作者，不能用资料更新时间替代。
6. 截断与读取失败不会伪装成完整统计或 0；提交频次不生成项目完成百分比。
7. AI 在发送前有可审阅范围，敏感文件默认排除；故意带指令的提交说明／Diff 不能触发命令、文件读取或任务状态写入；摘要中的结论能关联到真实提交／文件。
8. 日志和三种任务状态重启后保留；编辑冲突、重复提交关联、跨项目关联、提交对象缺失、项目重新定位及移除归档都经过验证。
9. 版本 1 原库升级、版本 1 备份导入、版本 2 备份往返、损坏／不合法关联备份回滚都使用临时数据库验证；失败不能破坏当前项目与工作记录。
10. 原有项目管理、标签、AI 助手、API 配置和备份回归通过；375、760、800、1060、1280、1536px 下无页面横向溢出，Diff 仅在自身容器按需横向滚动。
11. 使用真实临时 Git 仓库与本地模拟模型完成自动化验证，再单独记录原生 GUI、真实供应商与安装包验证；浏览器不模拟真实 Git 状态或提交记录。

用户已确认统计口径并授权实施。实施进度及验收证据分别见对应实施计划与验收记录；不创建 Git 提交。
