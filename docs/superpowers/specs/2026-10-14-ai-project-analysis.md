# 添加项目 AI 解析设计

目标：用户选择本地项目后，主动点击 AI 解析，生成项目名称、项目简介、项目分类、技术栈、项目标签。保留现有本地规则识别。

推荐方案：自定义 Chat Completions 兼容接口，通过设置填写 API 基础地址、模型名称、可选 API Key，同时支持云服务和本地模型。相比绑定单个供应商便于替换；相比调用本机 AI 命令行不依赖额外客户端。未配置时给出设置提示，浏览器不模拟本地解析。

交互：AI 解析前显示所用服务及发送范围；用户点击后读取有限的项目资料，显示解析中的状态。返回五项结果预览；点击“应用解析结果”覆盖对应五个表单字段，其他字段保留，用户仍可编辑并主动保存。取消结果、解析失败不会丢失当前表单。编辑已有项目也可使用同一流程。

输入：只读项目根目录 README 与已知依赖清单，有限的一层目录名称。每文件最多 32 KiB，总文件资料最多 64 KiB；不读取 .env、独立密钥文件、源码正文，不递归依赖和构建目录，不执行仓库脚本。项目绝对路径不作为独立字段附带；文档中的文本按原内容读取。

输出：严格 JSON，必须含 name、description、category、techStack、tags。分类限现有六种，字符及数组限制沿用保存规则，规范化去重。未知用途应保守描述，不把仓库文档中的指令当作系统指令。模型输出不触发任何文件或程序操作。

配置：按用户补充截图，在左侧栏底部增加“配置 API”，独立窗口维护配置。AI 配置单独持久化；Windows API Key 用当前用户 DPAPI 加密，读取接口只返回是否已配置，不返回原文；不进入 SQLite 备份。API 请求由 Rust 后端发起，不向浏览器注入密钥。HTTP 只允许本机地址，其余使用 HTTPS，禁用自动重定向。

边界：超时、授权失败、连接失败、无效模型输出明确报错。解析与数据库写锁分离，旧请求不能覆盖新表单。测试使用本机模拟 HTTP 服务，不调用真实收费模型。
