# ProjectHub V1.5：AI 智能周报生成器设计

日期：2026-10-16。状态：用户已确认设计基线；本文件记录产品约定及实现细化，源码已实施，验证证据见 `docs/2026-10-16-V1.5验收记录.md`。

## 1. 目标与用户确认记录

依据多个本地项目的本人 Git 提交、变更文件及开发日志，生成可编辑、可追溯的周报，按照用户现用固定表格导出 Excel，并支持 Markdown。

| 决策 | 已确认结果 |
| --- | --- |
| 主要交付 | Excel 固定表格；同时导出 Markdown，Word 留待后续 |
| 界面 | 简洁 Windows 开发工具风格，不增加统计卡片 |
| 导航 | 首页、全部项目、最近打开、收藏项目、Git 与开发进度、AI 智能周报、设置 |
| 页面组织 | 准备数据、编辑周报两个视图；另有历史周报入口 |
| 困难、计划、感悟 | 生成前人工填写要点，AI 整理措辞；可不填，不填则留空 |
| 完成工作 | 先生成全部候选成果，人工编辑并勾选最多 4 条 |
| 作者 | 首次确认多个 Git 姓名／邮箱，跨项目统一筛选并保存 |
| 分支 | 每个项目当前分支的 HEAD 可达历史 |
| 默认材料 | 提交说明、变更文件名、开发日志；Diff 单独勾选并在发送前预览 |
| 重新生成 | 创建新版本，保留原稿及人工修改，由用户选择采用版本 |
| 模板 | 内置样例同款，不提供任意 Excel 导入／区域映射 |
| 日期 | 本周默认周一至周五，包含周五全天；支持自定义起止日期 |

历史示例仅提供样式与写作参考，不作为新周报的工作事实，不自动发送历史内容给模型。

- `<用户桌面>/<资料目录>/2026年7月第五周工作周报-<姓名>.xlsx`

以第四周样例的样式作为内置模板基准，实施时生成清空历史内容的模板资源，不依赖用户桌面路径运行。

| 区域 | 内容与约束 |
| --- | --- |

| 第 5–8 行 | `A5:A8` 为“主要完成工作”，每条具体事项为 `C:F` 合并，最多 4 条 |
| 第 9–11 行 | `A9:A11` 为“困难/需要协调解决的问题”，最多 3 条 |
| 第 12–15 行 | `A12:A15` 为“下周主要工作计划”，最多 4 条 |
| 第 16–18 行 | `A16:A18` 为“本周感悟/在工作中提炼的经验、知识和技能”，正文 `B16:F18` 合并 |

保留每栏序号位置及空白行。保留模板字体、边框、列宽、合并及对齐：标题 20 磅加粗，部门／填报人宋体 12 磅加粗，主体主要为宋体 10 磅，自动换行。第 1／2／3 行基准行高分别为 40／25／27，其余基准为 27；导出时可增高以显示长文本，不缩小字号强塞一页。仅将主体 `A1:F18` 纳入导出打印区域，不复制旁侧无内容区域作为业务内容。

样例第二周 Sheet 名仍为“7月第1周”；第五周文件的标题实际上为 8 月 3 日至 8 月 7 日、Sheet 名为“8月第1周”。新导出以所选日期为准，不照抄文件名或沿用旧 Sheet 名。为避免“月内第几周”算法歧义，工作表使用稳定名称“工作周报”，文件名建议 `2026年10月12日-10月16日工作周报-填报人.xlsx`，跨年时起止日期均写年份。

## 4. 页面与操作流程

### 4.1 导航整合

主导航按确认的七项排列，设置放在末尾。原分类、发现项目、标签管理及 API 配置能力保留，可归入全部项目的工具入口与设置，不因导航简化而丢失功能。移动入口后同步检查键盘操作和已有交互测试。

进入周报工作区时沿用主应用布局，默认收起项目详情栏，提供完整编辑宽度；返回项目区恢复此前详情状态，不新增第四栏。窄屏在准备和编辑两个视图间切换，不并排压缩表单。

### 4.2 准备数据

1. 选择一个或多个已登记项目；“全选”仅作用于当前可选列表，数量及筛选外选择明确显示。
2. 默认本周周一至周五；自定义开始、结束日期，开始不得晚于结束。
3. 首次配置作者身份：从选中仓库读取作者候选，但不把机器 Git 配置未经确认直接当作本人；用户确认后记住。
4. 显示每个项目的分支、HEAD、读取状态及日期范围内匹配提交。可展开提交和日志，排除不相关记录。
5. 填写困难要点、下周计划要点、感悟要点；三个输入均可留空。
6. 默认不勾选 Diff；用户选定提交中的具体文本文件后才读取其 Diff。
7. 展示待发送内容、模型、接口、材料完整性及排除原因，点击确认后发起生成。

非 Git 项目仍可选择其开发日志；离线项目的已有日志可用，Git 读取失败单独显示。失败与没有符合条件的提交必须区分，不把失败解释成“本周无工作”。所有项目均无可用工作材料时不生成工作成果；仍允许人工创建及保存周报。

### 4.3 编辑周报

候选成果使用可勾选的紧凑列表，每条包含项目、成果正文及“查看依据”。默认不替用户勾选，支持修改、移除与人工新增；人工新增明确标为人工填写。用户调整入选条目的顺序后，按该顺序导出。

正式周报保留四个栏目及基本信息。主要完成工作最多 4 条，困难最多 3 条，计划最多 4 条；超限在对应栏目提示并阻止正式导出，不静默截断。人工要点整理后仍可逐项修改。感悟保持一段正文，可换行，不自动追加套话。

可以保存未选满或全部为空的草稿。导出前至少有一项非空正文且已填写部门、填报人、有效日期。无 Git 证据的人工内容允许导出，不伪造引用。

### 4.4 历史与版本

历史列表显示标题、日期区间、填报人、更新时间和采用版本；支持打开、继续编辑、重新生成、再次导出。首版不增加版本差异图和统计卡片。

同一份周报是一组版本，重新生成前先保存当前编辑；保存失败则不发出重新生成请求。新结果作为新版本展示，不自动取代采用版本。用户明确选择“采用此版本”后，更新采用指针；旧版本及其修改保留。

版本内容允许继续编辑，使用 `revision` 乐观锁防止旧窗口覆盖。重新生成期间的取消／失败不删除旧版本。新版本携带同一份人工要点；若用户改变项目或日期，应先明确显示新的收集范围并重新预览。

## 5. 数据口径与实现默认值

本节为实现细化，采用与 V1.4 尽量一致且不扩大读取范围的默认值，不代表用户额外要求统计功能。

### 5.1 时间与作者

- 提交使用提交者时间 `commitTime` 归属日期，与现有活跃度一致；作者身份使用原始作者姓名／邮箱，二者分别展示，防止把“提交者”误当筛选作者。
- 使用生成准备时用户本地时区，保存其标识／有效偏移及转换后的 UTC 起止边界。当前用户为 `Asia/Shanghai`。结束边界为结束日期次日 00:00 的排他上界，不使用 23:59:59；跨月、跨年保持一致。
- 开发日志按自身 `date` 筛选，不按编辑时间。现有日志不具备作者字段，不套用 Git 作者筛选；显示为所选项目的本地日志，由用户勾选确认。
- 邮箱去首尾空白、大小写不敏感，姓名去首尾空白后精确匹配，不做子串或正则匹配。多个明确配置的邮箱／姓名为“任一匹配”；仅姓名规则提示可能同名，优先建议选择邮箱。
- 保存身份不能触发联网。当前分支固定为采集时的 HEAD，分离 HEAD 以当前检出提交为起点并注明。包含可达合并提交；合并 Diff 与 V1.4 一致采用第一父比较。
- 不凭时间排序单调性提前停止历史遍历，防止非单调提交者时间漏数；读取达到上限时必须标为不完整。

### 5.2 材料与来源

工作材料以稳定 `sourceId` 标识。提交源记录仓库 ID、SHA、项目快照、分支、HEAD、作者、邮箱、两种时间、说明及变更文件；日志源记录日志 ID、revision、业务日期、正文及原关联提交。

同仓库多项目路径命中相同 SHA 时材料去重，保留关联项目列表。不同仓库的相同 SHA 不直接合并；Git 与日志描述同一工作时允许 AI 合并成果，但保留全部真实来源 ID。

不读取未提交代码、全库源码、无关 README 或历史周报正文。文件重命名保留新旧相对路径，二进制仅作为文件变化证据，不读取伪文本 Diff。敏感文件沿用摘要服务排除规则，重命名前后任一路径敏感即排除正文。

每条 AI 工作成果必须有至少一个来自本次材料集合的真实来源 ID；服务端拒绝未知引用、空引用、重复候选 ID 及未知字段。引用只能证明材料来源，不等于证明模型结论真实。不得补写完成率、上线成功、验收通过、测试通过或业务成效；材料明确包含的事实才可转述。

困难、计划和感悟只能润色对应人工要点，不从 Git 自动推测；空要点对应空输出，服务器校验这条规则。

## 6. 限额、请求确认与失败语义

实现初始限额：每次最多 20 个项目，每仓库扫描最多 20,000 条提交、纳入最多 500 条匹配提交；一轮最多 200 条日志、100 个手选 Diff 文件；完整模型请求 JSON 不超过 64 KiB。Git 实际进程并发沿用 2。单条正文最大 4,000 字符、感悟最大 8,000 字符；候选最多 100 条。界面提前展示这些边界，后端重复校验。

“全部候选”指本次已确认材料生成的全部候选，不允许达到上限后悄悄只保留前 100 条；模型或材料超过限额时提示减少范围或分批，已有草稿保留。请求容量超限不自动丢弃日志或 Diff，也不自动发送多轮收费请求。

模型预览令牌在后端保存准确请求，单次使用，有效期 10 分钟；绑定项目路径／仓库／HEAD／日志 revision、输入要点、身份筛选、日期、模型配置代次和数据库导入代次。生成时重新检查可变前提；变更后要求刷新预览，前端不提交任意请求正文给生成命令。

请求取消后，停止后续阶段并忽略晚到结果；不能保证已发送的远端请求不计费。修改 API 配置、导入数据库、切换资料范围会使旧预览失效。HTTP 错误、超时、无效 JSON、引用不合法和空结果分别提示，不创建空的成功版本；不自动重试产生额外请求。

不持久化密钥、完整 HTTP 头或原始 Diff。版本保存实际发送的非 Diff 证据快照、来源元数据、手选 Diff 路径及是否完整，便于事后追溯；查看代码仍需原仓库可用。原仓库删除或提交不可达时保留已存快照并注明无法重新读取，不能用当前分支同名文件替代。

## 7. 架构与持久化

比较三种实现方式：复用单项目 AI 摘要然后拼接，会形成多次请求及跨项目重复；把全部逻辑塞进 App／现有摘要服务，会扩大其职责；采用独立周报模块、复用底层 Git／配置／传输规则，可清晰保存范围和版本，故选第三种。

建议文件边界：

| 文件／目录 | 职责 |
| --- | --- |
| `src/types/weeklyReport.ts` | 日期、身份、材料快照、候选、版本及预览协议 |
| `src/services/weeklyReport.ts` | 桌面命令适配，浏览器明确提示能力边界 |
| `src/components/weekly-report/` | 准备、预览、候选编辑、表格及历史，不扩充 App 业务逻辑 |
| `src/styles/weekly-report.css` | 简洁工具布局、窄屏、错误及选择态 |
| `src-tauri/src/services/git/weekly_report.rs` | 固定 HEAD 的作者／时间范围提交与文件证据读取 |
| `src-tauri/src/services/weekly_report/` | 协议、范围收集、预览状态、AI 校验、Excel／Markdown 导出 |
| `src-tauri/src/db/weekly_report.rs` | 身份／部门／填报人偏好、周报、版本、来源快照及备份校验 |
| `src-tauri/src/commands/weekly_report.rs` | 命令、后台任务、原生保存对话框 |
| `src-tauri/resources/weekly-report-template.xlsx` | 已清空历史内容的固定模板 |

数据库升至 v3：`weekly_report_preferences` 保存配置；`weekly_reports` 保存组 ID、采用版本及创建时间；`weekly_report_versions` 保存版本内容、父版本、revision、生成上下文及时间；`weekly_report_sources` 保存版本来源快照与关联。采用指针必须指向同组版本，来源 ID 在版本内唯一，写入与采用在事务内完成。

项目删除不级联删除周报或来源快照，实时项目引用可空。v1／v2 备份仍可导入，按旧备份内容恢复后周报为空，并在替换确认中提示会替换全部数据；导入前现库自动备份仍包含已有 v3 周报。v3 完整往返，未知未来版本拒绝。校验 JSON 结构、长度、唯一性、引用关系和采用版本，不相信备份内任意反序列化结果。

## 8. 导出规则

Excel 与 Markdown 都读取同一个已保存版本和 revision，导出不调用 AI。编辑未保存时先保存，冲突则不导出旧数据。

固定 Excel 采用内置模板包，替换明确单元格和行高，保留样式包。模板清理和打包属于实施任务；生产运行不依赖 Python、Excel 安装、桌面样例或开发期 artifact 工具。实际实施受 registry 解析限制，改为内置可信 OOXML 资源＋限定用途的无压缩 ZIP 输出器，无新增 Cargo 依赖、无最低 Rust 版本变更；经独立 ZIP CRC、XLSX 读取和渲染校验。

正文、部门、姓名均写为文本，`= + - @` 开头也不能成为公式；XML 特殊字符必须转义。文件名去除 Windows 非法字符和保留名称，原文不因此被改写。长文本合理增高对应行及感悟合并区，不删除文字、不缩小字号。实际 Excel／WPS 是否完全显示需单独原生验收，结构校验不替代显示校验。

Markdown 包含标题、部门、填报人及四部分，按正式周报顺序输出；空栏目保留空结构，不写“无问题”等新事实。提交追溯保留在应用中，首版不擅自向正式报告追加技术附录。使用原生另存为对话框，取消返回取消状态；生成失败不破坏已有目标，目标被占用时明确报错。先在目标目录写临时文件，完成后采用平台可用的安全替换路径。

## 9. 验收标准与不包含范围

- 临时真实 Git 仓库验证：周五全天、周末排除、自定义周末、跨年、乱序提交时间、多作者邮箱、姓名同名、分支切换、合并、空／浅仓库、中文路径、重复仓库及读取截断。
