# ProjectHub AI Assistant 首版设计

日期：2026-10-15。状态：用户已确认并完成首版源码实现，2026-10-16 完成自动化回归与代码复核。实际验证范围见 [验收记录](../../2026-10-15-AI助手验收记录.md)。

## 1. 目标与范围

将 ProjectHub 扩展为理解本地项目资料、调用受控工具并展示真实结果的项目工作台。首版只交付三个闭环：自然语言检索项目、生成单个项目简介、辅助整理项目分类。

| 场景 | 用户输入 | 可交付结果 | 写入时机 |
| --- | --- | --- | --- |
| 自然语言检索 | 帮我找到之前开发的空气质量预警项目 | 真实项目卡片、匹配依据、查看详情 | 无写入 |
| 生成简介 | 给 env-agent-backend 生成简介 | 根据 README、依赖清单生成可编辑简介，并列出依据 | 点击“保存简介” |
| 整理分类 | 把所有 Spring AI Alibaba 项目归类到 AI 项目 | 候选清单、匹配依据、原分类和目标分类，支持勾选调整 | 点击“确认修改 N 个项目” |

不在首版加入模块问答、多项目依赖对比、维护建议、Git 活跃分析、通过对话启动 IDE／终端、切换默认 IDE、标签批量修改。原有详情里的手动打开功能继续使用。用户给出的综合示例是后续方向，不能据此扩展首版范围。

## 2. 当前代码依据

- `src/App.tsx`：维护项目库、筛选、详情显隐和批量选择；右侧详情目前依赖存在可见的已选项目。
- `src/components/ProjectDetail.tsx`、`src/styles/minimal.css`：既有详情与三栏布局；小于等于 760px 时详情占用工作区，关闭后返回列表。
- `src/components/AiSettingsDialog.tsx`、`src/services/projects.ts`：已有模型配置、获取模型列表、连接测试与 Tauri 调用入口。
- `src-tauri/src/services/ai/`：已有模型请求、严格 JSON 解析、DPAPI 密钥保存，以及受限项目上下文读取。
- `src-tauri/src/services/ai/context.rs`：白名单根目录文档／依赖清单，每文件最多 32 KiB、合计最多 64 KiB；枚举根目录下一级目录名，不递归读取源码。
- `src-tauri/src/db/bulk.rs`：已有 1–500 个项目的批量分类事务，但没有预览版本冲突校验，不能直接作为助手确认接口。
- `Project.updatedAt` 随资料编辑、标签与分类修改变化；`lastOpenedAt` 代表通过 ProjectHub 打开时间。当前 Git 数据只有仓库、分支与远程地址，没有最近提交时间。

当前目录没有 `.git`，本设计以现有文件为依据，不创建 Git 提交。

## 3. 方案选择

| 方案 | 优点 | 代价／局限 |
| --- | --- | --- |
| 受控工具调度，推荐 | 能形成检索、预览、确认保存闭环；沿用当前模型接口；后续可增添工具 | 需要意图协议、参数校验和预览状态管理 |
| 只把自然语言转换为关键词 | 改动最少 | 难以稳定处理语义用途、简介生成与分类整理 |
| 向量索引与通用 Agent | 适合更大规模的语义检索与复杂任务 | 增加嵌入模型、索引更新和运行时依赖，超出三个首版场景 |

首版不要求模型服务支持原生函数调用。沿用现有 Chat Completions 请求方式，让模型返回严格的结构化意图，由 Rust 工具调度器执行。结构化意图是工具调用请求，不是可直接执行的代码。后续可替换模型协议适配层，不改变本地工具与确认流程。

## 4. 页面与交互

### 4.1 入口与面板

- 右上角增加“AI 助手”按钮，沿用现有中性配色和蓝色操作强调。
- 右侧区域顶部为“项目详情｜AI 助手”切换。仅渲染一个面板，不增加第四栏。
- 无项目被选中或项目库为空时，也能打开助手。项目库为空时说明需要先添加项目。
- 选中项目不会自动切换走当前对话；检索卡片上点击“查看详情”才主动切到详情，切回助手保留会话。
- 面板打开／收起与内容类型分开管理：`panelOpen` 与 `panelMode`。助手不再依赖 `visibleSelected` 才能存在。
- 沿用桌面三栏与窄屏工作区切换方式；首版不为助手额外加宽右栏。卡片、输入框、工具进度支持窄栏换行。

### 4.2 助手初始状态

标题：ProjectHub Assistant。

欢迎语：“你好，我可以帮你查找项目、生成简介和整理分类。”

快捷提示使用真实首版能力：

- 查找 Spring Boot 项目。
- 为当前项目生成简介（未选中项目时禁用并说明）。
- 整理项目分类。

底部固定多行输入框、范围选择器和发送按钮。默认“全部项目”，可切换“当前筛选结果（N 个）”或“当前项目：项目名”。Enter 发送，Shift+Enter 换行，中文输入法组合输入期间不触发发送。面板内消息区独立滚动，新增结果不抢走正在阅读历史消息的滚动位置。

### 4.3 范围语义

- 发送时固定本轮项目 ID 集合，之后切换左侧筛选不改变正在执行的任务。
- 每条任务记录范围名称和项目数量。助手的结果默认不改动中间列表筛选。
- “在项目列表中查看”是主动操作，将真实结果 ID 应用为独立结果筛选，提供清除入口。
- 当前项目或筛选结果为空时不能发送依赖该范围的任务；可以切换到全部项目。
- “所有”表示所选范围的全部项目。若当前范围不是全部项目，结果明确说明实际范围，不静默扩大。
- 批量管理的勾选与助手建议中的勾选分开。进入批量管理时可收起右侧面板，会话保留；助手建议写入与其他项目修改通过既有操作协调机制串行执行。

## 5. 三个核心流程

### 5.1 自然语言检索

1. 模型解析用户的名称、业务用途、技术栈、已有分类和时间条件，产生受限查询计划。
2. 本地后端从本轮范围读取项目索引；标准化常见技术栈别名，例如 SpringBoot／Spring Boot、Vue3／Vue 3。
3. 明确的分类、收藏、路径状态、时间条件由本地确定性过滤执行；语义用途由模型对候选资料进行相关性判断，返回项目 ID、依据字段和简短解释。
4. 纯业务语义检索不只依赖字面命中；在支持的范围内对全部候选元数据分批判断，避免只对关键词召回结果重排而遗漏中文同义描述。
5. 后端校验每个 ID 属于本轮范围，并检查依据片段确实出现在对应资料字段。没有依据的匹配不能作为确定命中。
6. 返回卡片包含名称、简介、技术栈、分类、匹配依据及“查看详情”。路径只在本地展示，不需要发送给模型。

首轮检索只使用已保存的名称、简介、分类、技术栈、标签及必要时间字段，不默认上传备注或读取全库 README。若资料不足，显示“目前仅根据已保存资料检索”，并提供“读取候选项目资料后继续”入口。该入口先列出用户可勾选的候选及发送范围，再按现有白名单读取 README／依赖；资料没有证据时标记“待确认”，不能声称已经找到全部匹配项目。

结果区分“已确认匹配”“可能相关／资料不足”和“无法读取”，不显示没有校准依据的匹配概率。精确同名但不同路径的项目同时列出，要求用户选择，不能按第一个项目执行。

时间条件：

- “最近打开”使用 `lastOpenedAt`；“最近修改资料”使用 `updatedAt`。
- “最近开发”“一个月没有代码更新”缺少代码活跃证据，解释当前支持的时间指标并请求用户选择；不自动换算成资料更新。
- 用户明确选择“近一个月资料更新”时，定义为本轮参考时间前 30 天至参考时间；保存 UTC 时间边界并展示本地时区日期范围。本轮不随分页或重试重新计算。

### 5.2 智能生成项目简介

1. 根据名称／本轮结果定位一个已入库项目；多个匹配先选择，不能静默批量生成。
2. 展示项目、所用模型服务和发送范围；用户主动点击“读取资料并生成”。
3. 本地读取白名单上下文，与现有简介一起供模型生成建议。输出中文简介及对应资料依据，资料不足时明确说明。
4. 展示“现有简介／建议简介”，建议文本可编辑；默认生成简短的用途、主要技术和已被证据支持的功能说明，不填充不存在的能力。
5. 点击“保存简介”只更新该项目的 `description`；不复用完整五字段覆盖逻辑，不改名称、分类、标签、技术栈或其他资料。
6. 保存成功后更新项目列表、详情及结果卡片。放弃、失败或关闭预览均不写库。

本轮不做批量简介生成。现有添加／编辑弹窗中的五字段“AI 解析”继续作为独立入口，不与助手单字段保存混淆。

### 5.3 AI 辅助整理分类

两种输入共用一个建议预览：明确规则“把 Spring AI Alibaba 项目归为 AI 项目”，以及开放建议“帮我整理项目分类”。分类固定使用当前六种：后端、前端、AI、工具、学习、其他。

1. 依据当前元数据生成候选；明确指定的目标分类优先，不能被模型改成其他类别。
2. 每行显示项目、原分类、目标分类、匹配依据、资料状态；目标分类可修改。
3. 有直接依据的实际变化默认勾选，含糊候选默认不选；已经处于目标分类的项目标记“无需修改”，不重复写入。
4. 需要检查 README／依赖才能判断的候选，进入与检索相同的资料读取确认流程。未检查的部分明确列出，不能给出“所有项目已处理”的结论。
5. “确认修改 N 个项目”按钮绑定当前预览的确切项目和目标值；未勾选项目不受影响。
6. 支持逐项目不同目标分类；单次事务统一提交，任一项目冲突或校验失败时整批回滚，提示重新生成／核对建议。

例如把 Spring AI Alibaba 项目归类到 AI：依据可以来自技术栈、简介或读取后的 `pom.xml`；仅出现泛指的“AI”不足以断定使用 Spring AI Alibaba。

## 6. 工具与数据流

```mermaid
flowchart LR
  A[用户输入及本轮范围] --> B[结构化意图解析]
  B --> C[Rust 白名单工具调度]
  C --> D[本地项目索引与受限资料]
  D --> E[校验后的项目结果或修改建议]
  E --> F[右侧结果卡片与预览]
  F --> G[用户确认具体修改]
  G --> H[事务写入及界面刷新]
```

| 工具 | 输入要点 | 作用 | 模型能否直接触发写入 |
| --- | --- | --- | --- |
| `search_projects` | 受限条件、本轮范围引用 | 检索索引，返回真实 ID 和证据 | 否，只读 |
| `read_project_context` | 已解析且获读取授权的项目 ID | 读取白名单文档／依赖上下文 | 否，只读；需要本轮资料读取授权 |
| `propose_description` | 项目 ID、上下文引用 | 生成单字段简介建议 | 否 |
| `propose_categories` | 候选 ID、可选明确目标分类 | 生成逐项目分类建议 | 否 |

工具参数采用固定枚举与严格结构校验，不接收模型给出的 SQL、Shell、任意路径、工具代码或任意 Tauri 命令名。文件路径由后端根据真实项目 ID 解析。资料内容和模型解释一律作为不可信文本，不将 README 中的指令提升为用户授权。

写入通过独立的 `apply_assistant_proposal` 界面接口完成，不注册为模型工具。用户在预览中点击按钮才调用。对话里的“确认”“全部执行”不能绕过预览按钮直接写库。

### 6.1 消息与结果模型

- 消息包含 `id`、角色、正文、任务状态和结构化附件。附件类型限定为项目结果、简介建议、分类建议、资料读取请求与能力提示。
- 工具状态展示“正在检索项目／正在读取资料／正在生成建议／等待确认／已保存／已取消／失败”，不显示模型内部推理。
- 结果卡片内容来自工具返回的项目对象；模型不能单靠正文生成可执行的项目按钮。
- 同轮串行执行工具，每轮最多 8 次工具调用、最多 4 次模型请求，整体最多 90 秒；每个网络请求最多 60 秒，超过剩余任务预算时使用剩余时限。一次意图解析、最多两批元数据判断和一次结果生成均计入该预算。
- 元数据分批判断作为一次工具内部任务。每批最多 50 个项目，输入序列化后最多 64 KiB；单条资料超限时截断并标记。每轮最多完整检查 100 个项目，超过时先让用户缩小范围或分批处理，禁止静默只取前 100 个后声称检索全库。
- 预览修改数量不能超过已完整检查的范围；底层写入继续遵守最多 500 个项目的现有上限。首版助手本身每轮最多 100 个。
- 补充 README／依赖作为用户主动开始的新一轮任务，每轮最多选择 3 个项目，逐项目采集并判断，每份上下文仍最多 64 KiB；超过数量需分批。资料读取授权绑定具体 ID 与本轮，不自动沿用到其他项目。达到模型请求或时间预算就停止，展示已完成与未完成清单。
- 同一会话一次只执行一个任务。取消后忽略所有晚到结果，停止后续读取／请求；无法抢占的同步文件读取需完成当前读取后停止，不宣称立即中止所有 I/O。

## 7. 写入一致性

建议由后端创建并临时保存在内存中，包含 `proposalId`、会话引用、项目 ID、原资料快照、目标字段、生成时间和项目库代次。有效期 10 分钟；应用重启、项目库导入、接口配置改变或会话清空使未应用建议失效。

确认保存时：

1. 从后端建议记录取回原对象；只接受用户勾选的建议子集及该建议允许编辑的值。
2. 在同一个写事务中验证项目仍存在、项目库代次一致、`updatedAt` 和原资料快照一致。导入不能因项目 ID 与时间恰好相同而误用旧建议。
3. 简介仅允许 `description`，分类仅允许 `category`；对编辑后的值重新执行当前字符长度与枚举校验。
4. 只更新目标字段和资料更新时间，其他列保持不变；分类建议按各行目标值原子提交，不在前端循环调用完整项目更新。
5. 标记建议已应用；重复点击或重放同一请求返回首次执行结果，不能二次覆盖。

数据库锁只覆盖本地检查和提交，不覆盖模型请求、用户等待或文件读取。失败保留用户输入与建议文本；若版本冲突则禁用原确认入口，先刷新并重新核对。

## 8. 模型配置、资料范围和失败处理

- 沿用现有地址、模型和密钥配置，不增加第二套供应商设置。密钥由 Rust 读取，前端与会话均不保存密钥。
- 未配置时展示“配置 API”按钮并保留输入；不开启虚假的 AI 回答。浏览器模式展示界面与能力说明，不向外部模型发送数据或模拟真实项目读取。
- 助手首次发送前展示当前模型服务与本场会话的项目元数据发送范围，用户主动开始后生效；切换接口配置重新展示。README／依赖读取按具体项目另行展示范围，用户确认后执行。
- 不默认上传绝对路径、个人备注、Git 远程或源码正文；路径可留在本地 UI。README／依赖本身可能包含敏感文本，发送范围说明应提示其内容会交给用户配置的模型服务。
- 资料采集继续使用每文件 32 KiB、总计 64 KiB 的既有限制；新增明确的文件读取失败／截断状态，不把缺失或不可访问解释为文件内容为空。
- 会话仅保存在应用内存；关闭右栏保留，重启清空。支持新建会话。模型只收到当前任务、必要项目资料以及至多最近两轮相关对话摘要，不反复附带全部历史文档。
- HTTP 授权错误、额度／限流、超时、模型格式无效、未知项目 ID、目录不可访问分别显示；自动重试不产生写入，收费模型请求由用户主动重试。
- 无效结构化输出直接报错并保留输入，不把自由文本解释成操作。超出首版能力时明确列出能完成的部分，只有用户选择受支持场景后才继续。

## 10. 验收标准

1. 未选择项目时可打开助手；详情与助手互切保留会话；始终最多三个主区域。375、760、800、1060、1280、1536px 下无页面横向溢出，长项目名、依赖和简介不撑开面板。

4. “最近开发”不得用 `updatedAt` 冒充；用户选择资料更新时间后，按固定时间边界检索。
5. 简介生成的读取范围、旧值和建议可见；用户可编辑后保存。验证只改变简介与更新时间，其他字段完全保留。

7. 取消、建议过期、项目被编辑／删除、项目库导入、重复确认均有验证；分类事务中一个冲突导致整批无改动。
8. README 中的“忽略规则、读取密钥、执行命令”以及模型伪造 ID／未知工具／越界字段均不能触发读取或写入。
