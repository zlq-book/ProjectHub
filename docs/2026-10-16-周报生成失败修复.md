# 周报生成失败修复

## 问题与证据

用户在 DeepSeek `deepseek-flash` 生成周报时看到“模型输出被截断或包含工具调用”。截图未包含接口原始响应，无法判断本次返回的是 `finish_reason=length` 还是空工具数组；没有读取或记录用户密钥，也没有向真实供应商重新发送业务材料。

源码存在两个相关问题：响应判断把所有 `tool_calls` 数组都当作工具调用，包含空数组；周报设置 6000 token 输出额度，但没有处理官方新模型默认开启的思考模式。根据 [DeepSeek 官方思考模式说明](https://api-docs.deepseek.com/guides/thinking_mode/)，默认开启思考，可通过 `thinking: {type: "disabled"}` 关闭。后者是本次截断的一种可能原因，不能从截图单独确认。

另复现了失败后的重试问题：后端在发送前已消费预览，前端失败后却保留弹窗，允许再次提交同一 token。

## 修改

- 空工具数组、null 或缺省字段均可正常读取正文；真实工具调用、旧式 function_call 和明确工具结束状态仍拒绝，不执行工具。
- 截断独立提示 `finish_reason=length`，若接口提供用量则显示输出 token 数，并提示减少材料／Diff 或更换非思考模型后重新预览。保留原稿，不尝试拼接残缺 JSON。
- 服务拦截、异常结束、空正文分别报错；不把思考内容当作周报，也不在错误中显示原始响应或思考正文。
- 仅针对 HTTPS 官方主机 `api.deepseek.com` 的 `deepseek-flash`／`deepseek-v4-pro`，周报请求显式关闭思考；自定义模型、其他兼容接口及相似域名保持通用参数。预览展示和最终发送仍使用同一个完整请求体。
- 失败后关闭已消费的发送预览，保留所选材料、人工要点与原稿；用户重新预览、确认后才再次发送，不自动重试或隐式增加模型调用。

## 验证

模拟 HTTP 回归测试在修改前复现：有效周报正文加 `tool_calls: []` 被错误拒绝。前端回归也在修改前复现：失败后旧预览弹窗未关闭。前端修改后全量 20 个测试文件、108 项测试通过。

周报后端专项 8 项通过，包含真实临时 Git 仓库与本地模拟 HTTP，校验了预览／发送一致、单次令牌、官方模型参数及异常响应处理。独立只读代码复核未发现阻断问题。真实 DeepSeek 调用、原生窗口和安装器运行不在本轮模拟验证范围内。

Rust 全量回归运行了 88 项，首次 85 项通过、3 项失败。两项明确报 Git 读取超时，另一项在工作区变化断言处失败。构建结束后对这三项串行复测，工作区变化断言及 Git 过滤测试通过，剩余 `services::development_summary::tests::preview_requires_confirmation_excludes_secrets_and_sends_only_reviewed_wire` 仍失败：模拟服务 `stream.read` 返回 Windows 10035／WouldBlock，客户端随后报摘要连接失败或超时。本轮未修改开发摘要生产代码或该测试，未扩大为其超时修复；不能据此声称 Rust 全量通过。周报专项在全量运行中也全部通过。
